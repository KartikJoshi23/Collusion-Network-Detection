The Algorithms, Explained Simply

What each box in the flowchart does and how it works — in everyday language.

Graph Neural Networks — the heart of the systembox 3a · used wherever risk is scored

What it does: scores every account or company by looking at who it deals with, not just what it looks like.

How it works: each node starts with a profile of numbers; in a few rounds every node blends its neighbours' profiles into its own, so a node inside a laundering ring ends up looking measurably different from a normal one.

GATv2 — attentionbox 3a · main model on the Bitcoin graph

What it does: learns which of a node's connections matter most and listens to those the hardest.

How it works: it computes an importance weight for every connection before blending — and those weights double as a first clue when explaining an alert.

GraphSAGE & R-GCN — direction and relation typesbox 3a · financial / procurement

What it does: treats “money in” differently from “money out”, and “won a tender” differently from “bought from”.

How it works: each direction and each relationship type gets its own learned mixing rule instead of one shared pot.

Focal loss — learning from 2% positivesbox 3a · trains every deep model

What it does: stops the model from lazily calling everything “innocent” (98% correct, 100% useless).

How it works: easy, already-correct examples earn almost no credit in training, so effort concentrates on the rare suspicious cases.

Autoencoders (DOMINANT & GAE) — anomalies without labelsbox 3b · the unsupervised arm

What it does: flags unusual nodes even where nobody ever labelled a crime.

How it works: a network learns to compress and rebuild the graph; whatever rebuilds badly is unusual. (Honest finding: weaker than the supervised models on our data — reported, not hidden.)

Calibration + ensemble — merging models fairlyflowchart box 4

What it does: combines several models without letting a loud weak one drown out a quiet strong one.

How it works: each model's scores become honest probabilities first (checked on held-out data), then they're averaged. Skip that first step and the ensemble collapses — we measured it.

Leiden grouping + de-duplication — the short queueflowchart box 5

What it does: turns hundreds of thousands of node scores into a few hundred group-shaped alerts.

How it works: a community-finding algorithm spots tightly-knit clusters; clusters become alerts; overlapping alerts are removed from the top down so no analyst reads the same case twice.

XGBoost baselines — the honesty yardstickbox 3d · every headline comparison

What it does: fields the strongest classic method (boosted decision trees) before any deep-learning claim is made.

How it works: hundreds of small decision trees, each correcting the last. On the Bitcoin data the trees still win — we report that openly, with a statistical significance test.

PGExplainer — “show me why”flowchart box 6 · evidence for every top alert

What it does: answers “which few connections made the model raise this alert?”

How it works: a small helper network keeps only the links the prediction truly depends on — then each explanation is verified: remove those links and the alert should collapse; keep only them and it should stand.

Pattern matcher + official red flagsbox 6 · runs on every alert, no AI involved

What it does: checks each alert against nine known collusion shapes and cites the official FATF / OECD red flag each corresponds to.

How it works: hand-written graph rules search the alert's neighbourhood — evidence that stands even if you distrust the neural network entirely.

The Copilot's guardrails — an AI that can't make things upflowchart box 8 · wrapped around every answer

What it does: lets investigators question the system in plain English without the usual AI risks.

How it works: the Copilot may only read published results; every number must literally appear in what it looked up; accusing phrases are rewritten automatically; a 24-question exam gates every release.

Statistical rigor — why the numbers can be trustedbehind every published result

What it does: makes sure no result is a lucky accident.

How it works: every headline model is retrained five times with different random starts and reported with its spread; comparisons are re-checked thousands of times on resampled data; every country and market takes a turn being fully held out to prove the system works on places it never saw.

The Data

Six public datasets, two crimes, nothing private and nothing personal. Every number on this page was measured from our own converted copy of the data — not copied out of the original papers. Raw files are never stored in our code; we ship a download script plus a fingerprint per file, so anyone can fetch exactly the same data and prove it is the same.

Why we need it: it is about 50 times bigger than Mendeley and has no answer key, so it is the closest thing we have to real deployment. We plant fake cartels in it and measure how many we recover.

Read this before quoting any Mendeley number. About 42% of its rows are cartel cases. The real world is nowhere near 42% cartels — that figure comes from how the researchers built the file: they deliberately collected known cartel cases alongside a comparison set. It is a study sample, not a snapshot of reality. So on that dataset a score may only ever be compared against its own guessing level of 0.358, and a Mendeley precision figure must never be presented as a real-world hit rate.
García’s dates are not trustworthy, and that changed our design. When we measured the dates in that file we found 36,453 dots stamped 1970 — the default a computer writes when a date is missing — another 21,385 with no date at all, and 33 rows reading 1677. Only a few thousand carry a believable year, between 1999 and 2013. That is why this is the one dataset we never split by time. We split it by market instead: train on some countries, test on a country the model has never seen. A dataset’s weaknesses should decide how you test it.
Only the Bitcoin datasets arrive with ready-made numbers. Elliptic ships 183 pre-computed numbers per payment and the wallet version ships 55. The four contract datasets ship none — every number the models use there is one we computed ourselves from the network shape. That single fact explains a result we report openly: on Elliptic the old-fashioned decision-tree method wins, because the network information has already been squeezed into columns and handed to it for free.

What One Row Actually Looks Like

All six datasets are converted into the same three tables. After that conversion the system genuinely cannot tell which crime it is looking at — a bank account and a construction firm arrive as the same kind of object. These are the real column names.

Why we show you the columns and not the contents. These files hold the names of real companies that were investigated for cartel behaviour. Printing a few of those names onto a slide, next to the word “cartel”, is exactly the harm this project is built to avoid — a screening signal is not a finding of guilt and must never be published as one. So the structure is public, and the names stay in the files.

What the Copilot Actually Knows

The assistant has two sources of knowledge and no others. It cannot answer from memory, and it cannot reach anything a person looking at the dashboard could not reach.

1 — The reference library (the words)

A small hand-curated set of 29 short passages. Each has an id, and any answer using one must quote that id — so every claim can be traced back to the passage it came from.

15our own vocabulary — what a risk score means, what a case is, what counts as a hit
5FATF money-laundering warning signs
5OECD bid-rigging warning signs
4method notes explaining how those two link to our patterns
FATF-STRUCT-01FATF-LAYER-01 FATF-LAYER-02FATF-CIRC-01 FATF-SHELL-01OECD-ROT-01 OECD-COVER-01OECD-ALLOC-01 OECD-CLUST-01OECD-LINK-01 CG-RISK-01CG-PREC-01 CG-FIDELITY-01CG-SCREEN-01 …

How it searches: plain keyword scoring, run inside our own service, returning the best four passages. No external search service and no internet call.

2 — The results themselves (the numbers)

For anything factual, it does not recall — it looks it up, live, through seven read-only tools. Every lookup appears on screen as it happens.

list_tableswhat result tables exist
describe_tablewhat columns a table has
run_sqlone read-only query, capped at 50 rows
list_alertsthe ranked cases for a dataset
get_alertone case in full
get_explanationthat case’s evidence file
get_metricsthe published scores for a dataset

Read-only is enforced, not requested. There is no tool that writes. The assistant physically cannot change a score, a case or a result — it sits below the trust boundary like everything else.

It is a searchable library, not a “knowledge graph” — get this right on stage. People often assume an assistant like this sits on a knowledge graph. Ours does not, and claiming otherwise is an easy question to get caught on. We did try a vector database early on and removed it: with only 29 passages, plain keyword search returned the same answers, added no dependency, and is far easier to explain and audit.

There is a graph in this system — it is the data itself, the dots and lines the models are trained on — and the assistant reaches it through the read-only lookups above. So the accurate sentence is: “a small cited reference library for the words, and read-only queries against the graph for the numbers.”
